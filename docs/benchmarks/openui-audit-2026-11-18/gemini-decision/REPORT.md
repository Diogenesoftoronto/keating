# What happens when Gemini Decision reviews a Keating lesson?

**November 18, 2026.** Using Gemini Decision 1 for planning and review produced the same two requested MiniMax interfaces as Jev. It also prevented a correct one-word answer from reaching the learner. On an identical copy of the tutor’s `16.` reply, Jev scored answer leakage at **0.350** and released it. Gemini scored it at **0.737** and withheld it. The learner had explicitly asked for the answer. Each tutor received a prediction cue, a request to explore a variable without a quiz, and a short-answer control. The two action cues described what the learner wanted to do in ordinary language. ## Planning and release on fixed inputs

**Choosing an interface.** On six planning probes with predeclared expectations, Jev recognized the assessment preference and offered an acceptable interface or pause on **6/6**. Gemini Decision did each on **5/6**. The missed prompt asked to vary the number of classes in a club-membership simulation and ended “No more questions yet.” Jev assigned 0.73 to assessment being declined and Keating offered a Simulation. Gemini assigned 0.421, which the policy treated as uncertain, and Keating offered nothing. On the independent-choice prompt, Gemini offered just a Question and Jev offered three options. Both satisfied the rubric. The exact offers agreed on **3/6**. The projector had previously been refined using the missed simulation case, so Jev’s 6/6 is an in-sample result. [Fixed inputs and expectations](./frozen/requests.json) · [Paired decisions](./frozen/comparison.json)

**Reviewing the same drafts.** On nine repaired MiniMax drafts under the same gate, Jev released **6/9** and Gemini released **8/9**. They agreed on seven, including an ordering question that both held over suspected leakage. Gemini’s two extra approvals illustrate the tradeoff. The French flashcards kept translations on the backs as the learner asked. Jev blocked them for repeating a checkpoint. The Python exercise explained exactly which index the loop skipped before asking the learner to predict the output. Jev blocked it for leakage. These are observations about the recorded material. The nine drafts were selected from earlier failures and carry no independent pass/fail rating for teaching quality. Google returned nine of fifteen frozen decisions on the first pass. Six explicit rate-limit rejections were resubmitted after the reported quota window, bringing measured coverage to fifteen of fifteen. [Fixed draft text](./frozen/requests.json) · [Both reviewers’ decisions and blockers](./frozen/comparison.json) · [First-pass coverage](./frozen/first-pass-comparison.json)

**Why the direct answer was withheld.** Gemini’s planner selected no activity and scored the request for plain text at 0.934. The tutor followed that instruction. The review question asks whether a reply reveals the answer to a learner checkpoint. Keating applies an uncalibrated fail threshold of 0.60. On the two distinct new MiniMax drafts the leakage scores were 0.675 and 0.791. A follow-up then held the historical turn, literal reply `16.`, all 44 review questions and gate fixed. Gemini withheld that same reply solely for leakage. Jev released it. This follow-up was chosen after observing the failure and sits outside the original fifteen frozen cases. ## Product decision

Keep Jev as the default reviewer for now. This comparison found no gain in released OpenUI from replacing it, and it reproduced an unnecessary veto on a correct direct answer. Keep interface offers advisory so the tutor can choose a suitable control. Before giving another reviewer authority to block a reply, test when the checkpoint-leak rule applies. A plain answer with no pending assessment should pass a direct-answer regression. Score active assessments, genuine prediction questions and flashcards that hide the answer until the learner responds on that same test. Tune each provider’s veto threshold against those labelled cases. The classroom frequency is still unknown. The earlier release audit covered a wider set of synthetic opportunities and the inspector can measure future classroom traces. ## Reproduce and investigate

The local application harness calls Google’s official Decisions API with the pinned model `gemini-decision-1` for planning and review. The separately named `gemini-3.1-flash-lite` writes tutor replies. The transport records raw typed decisions, checks the question vocabulary, and returns the scores to the existing gate. Successful Google responses omitted a returned model revision. The receipts preserve the requested model and endpoint. The adapter is available in the evaluation harness. Classroom routing still uses its configured providers. [Google’s Decisions API](https://aistudio.google.com/docs/decisions-api) · [Evaluation adapter](../../../../scripts/openui-diagnostics/gemini-decision.ts) · [Runner protocol](./protocol.json)

The v2.1 gate uses the historical label `jev` for several semantic review checks. The comparison kept that shared release logic fixed for both arms. Use the transport receipt and the exported `decisionModel` to identify who scored a turn. [Gate rules](../../../../packages/learner-contracts/src/judgement/teaching-drafts/policy.ts) · [Paired review provenance](./frozen/comparison.json)

Use **Settings → Diagnostics → Interface use → Jev and Gemini Decision 1** to select a tutor, judge, learner cue and observation stage. Under **Inspect turns**, select **Reply withheld** to find blocked text answers. The final-reply view includes known withholdings among its measured turns. The comparison also shows the rate among turns that produced a complete tutor candidate. The offline inspector has the same controls. The CLI and WebMCP accept the same decision-model filter.
