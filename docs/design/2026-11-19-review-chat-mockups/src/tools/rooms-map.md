## Entry and permissions

- All three are lazy root routes with global Nav and the shared Courses access gate: `/rooms` → Rooms, `/rooms/$roomId` → RoomWorkspace, `/rooms/join/$token` → RoomJoin. Nav includes “Rooms.” No room-specific route flag appears here. `web/src/App.tsx:123,365`, `web/src/components/Nav.tsx:56`, `Rooms.tsx:172`, `RoomWorkspace.tsx:269`, `RoomJoin.tsx:139`
- All room APIs require a course product identity. Hosted uses a linked course session or Not Organic with `keating:courses`; with server `NOTORGANIC_ENABLED` unset/off (see `web/src/notorganic-provider/server.ts:72`) the server issues a stable browser-local cookie identity. Nonproduction can use `KEATING_COURSES_DEV_ACCOUNT_ID`. The client’s `VITE_NOTORGANIC_ENABLED` gate affects “Check account” recovery. Lists are account-scoped; room snapshots require membership. Course owner/teacher can create a lesson room; course members can join without a link, with derived roles following course membership. Explicit invitations and host-assigned grants are separate. `web/server/api/rooms/[...path].ts:162`, `web/server/utils/course-session.ts:19,52`, `web/src/notorganic-provider/index.ts:279`, `docs/study-rooms.md:3`
- Host/teacher oversee (guidance, review, hide, mute, pause, settings, end/reopen); only host changes other members’ roles, removes teachers, or deletes. Host invites Learner/Teacher/Observer, teacher Learner/Observer, learner only Learner when enabled. Open + unmuted + non-observer can post. Facilitating also depends on settings and teacher review. Observers read/export. `operations.ts:380,895`, `room-ui.ts:217`, `RoomSettingsPanel.tsx:127`
