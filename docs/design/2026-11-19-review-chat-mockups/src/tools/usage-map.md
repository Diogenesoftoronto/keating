## Data provenance, responsive notes and rough edges

- Browser session metadata is fetched via the session store after initialization and cached in a module promise. Session metadata aggregates saved message usage, including reported cost components and totals; the page sums positive finite saved totals and applies no price schedule of its own. The gateway ledger instead uses actual billed micros per request and hosted wallet available micros. (U:32, 117–123; hooks/session-metadata.ts:130–155; keating/app-storage.ts:79–82; S:42–56, 147–181)
- Usage grids: four-tile block 1/2/4 columns at base/sm/lg; artifacts 1/3 at base/sm; recent/deepest stack then `1.25fr / 0.75fr` at lg; chart trio stacks until lg. Period, badges, portable actions and credits header wrap; portable actions right-align at xl. Recent rows min `9rem`, preview four-line clamp, title and model badge ellipsize. (U:63–114; C:49–52, 64, 87, 113–116; pages/training-data.css:56–102)
- Vocabulary: global “Usage”, header “Learning activity”; same messageCount called “Socratic turns”, “messages” and “turns”; missing model “Model not recorded”, “Unknown model” or omitted. “Estimated spend” / “Est. cost” are local estimates, “Keating credits” / “Charged” are gateway settlement. “Teaching materials” excludes verifications counted under “Topic mix” artifacts. “Self-improvement runs” includes “Improvement attempts”; detailed panel calls this “Self-evolution health”. “Independent judgement”, “teaching estimates”, “Scorers” and “Score / resume missing” refer to related parts of the training scoring flow.
