## Routes and access
- /courses → library. /courses/join/$token → enrollment. /courses/$courseId → workspace, accepting optional validated ?lesson= and a hash for source return. Workspace remounts on course/lesson/hash identity changes. /learn and /learn/$courseId are separate self-paced routes. /chat accepts course, courseMode=create/edit and ask. (web/src/App.tsx:172–181,314–362; P/CourseWorkspace.tsx:47–53)
- All three shared-course pages bootstrap the browser course session, fetch /api/courses/session, and gate on ready. Account-change events cause a fresh check. Account modes are development/local/hosted. List and join keep global Nav while gating, workspace uses its own shell. (D/useCoursesAccess.ts:4–13,42–75; P/Courses.tsx:492–506; P/CourseJoin.tsx:190–197; P/CourseWorkspace.tsx:106–113)
- Roles are owner, teacher, student, peer. Owner/teacher get course editing, invitations and review; deck rights also extend to non-teachers when the “peer deck edits” setting is enabled. Read and Discuss are universal tabs; Build also appears for deck-only editors. Learner work visibility depends on teacher-access consent. (D/operations.ts:60–86; W/model.ts:32–48; C/CourseBuilder.tsx:2150–2272; C/CourseReviewPanel.tsx:139–158,257–258)
- Course routes themselves are registered unconditionally. VITE_NOTORGANIC_ENABLED gates the hosted recovery prompt, KEATING_COURSES_DEV_ACCOUNT_ID is a server development identity override, and KEATING_COURSES_PEAR_ENABLED controls optional Pear gateway behavior. Course collaboration rules separately control peer comments/reactions, peer recall-deck editing and teacher access policy. (web/src/App.tsx:344–362,398–401; web/src/notorganic-provider/index.ts:279; C/CoursesAccessGate.tsx:22–34; web/server/utils/course-session.ts:21; web/server/utils/course-pear-gateway.ts:125–132; C/CourseBuilder.tsx:2152–2208)
- Gate loading says “Checking your course workspace…”. Unavailable gate has “Hosted course workspace” or “Course workspace”, “A course is learning you can return to.”, “Detailed lessons, source material, shared notes, Anki cards, peer work, and teacher review stay together in one durable room.” Right panel says “A PLACE FOR YOUR NEXT QUESTION” and “Bring a subject you’re curious about. Keating helps you turn it into lessons, readings, and practice you can return to.” Max 58rem, stacked until md, then 1.1fr / minmax(18rem, 0.9fr). (C/CoursesAccessGate.tsx:36–82)
- Recovery shows server copy when supplied. Fallbacks are “Your hosted course account could not be verified.”, “The course API is not running. Start the full Keating web task, then retry.” and “Your course workspace is unavailable.” “Check account” opens the account prompt, or shows “Hosted course workspaces aren't available yet — that access is still being built. Courses run today with your own API keys.” “Retry course access” reruns the check; missing API also prints the Devenv command. (D/useCoursesAccess.ts:15–39,64–69; C/CoursesAccessGate.tsx:22–33,53–71)

## Vocabulary, responsive behavior and source-visible friction
- Library says “course” and “workspace”; learning view is Read/“Reading desk”/“course desk”. Outline calls hierarchy “The spine”, records are modules containing lessons. “Unit” is not a primary shared-course control. An exercise is “Worked exercise” in Read and question in Build; assignment is “Long-range assignment” or “Course assignment”; deck alternates “Cards”, “Recall deck”, “flashcard decks” and “Anki”. “Live room” is the roster rail; “Study rooms” are separate joinable rooms. “Teacher” describes authority that also applies to owners; learner-facing role badge may show student or peer.
