## 6. Prioritized findings

Severity is impact on finding, understanding or safely using a setting. Counts: **3 high, 7 medium, 3 low**.

1. **High — Modal focus and naming.** Opened through the real chat menu, active element was `body` and the dialog had no accessible name; modal attributes alone don't keep Tab within Settings. Nested provider editor adds another modal div, plus an unlabelled X. Use named modal semantics, focus entry and restoration, and a single active modal layer. The current shared model-picker already implements native dialog, initial search focus and return focus (`web/src/components/ModelPicker.tsx:35–67`). `web/src/components/SettingsDialog.tsx:250–280,293–304,399–415`, `web/src/components/settings/CustomProvidersSection.tsx:265–282`, `desktop-start.png`.
2. **High — Persistent preferences can be set without an intelligible or centrally reversible data boundary.** Crash-report permission lives exclusively on failure cards. Learning extraction is on by default under an advanced diagnostic disclosure and hosted setup copy says sign-in includes it. Judgement capture, durable judgement records, safe logs, raw logs, Arize, replay and public sharing all have separate effects. Settings reasoning sets the global preference only, while composer reasoning mutates current context plus the global preference and snapshot. Loading an existing session restores its own level, so a reload may still show the old level. Place the gates and overrides together with explicit next-chat/current-chat scope. `web/src/components/KeatingUiSettingsTab.tsx:306–336,401–426`, `web/src/components/AssistantChatPanel.tsx:3212–3228`, `web/src/hooks/{useKeatingAgent.tsx:177–189,agent/useAgentSessionLifecycle.ts:195–196}`.
