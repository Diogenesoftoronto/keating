WHAT TO BUILD
1. Four named stages instead of eight screens: "Question", "Model", "You", "Ready". A header with the logo, "Welcome to Keating", a stepper showing the four stages with the current one marked (accessible as "Step {n} of 4: {name}"), and the always-available "Go straight to chat" (Escape still does the same). Layout at desktop widths: a left stage (about a third of the width) holding the mascot at about 92px with a different `KeatingBot` state per stage (greeting, thinking or connecting, listening, settled: keep the existing states where they map), the line "Keating teaches by asking." and the one-sentence explanation, over `ShaderSurface effect="field"`; the right side holds the stage content with a footer row (Back on the left after stage 1, the primary on the right). On narrow screens the stage column collapses to a small mascot row above the content and the primary button is full width at the bottom.
2. Stage 1, Question: eyebrow "1 of 4 · Your question"; heading "What would you like to understand?"; "A starting point, not a contract. It goes into the composer for you to review and send."; the goal textarea (same field, limit and persistence as the existing goal on "Your learning"); three example chips that fill the field (take three prompts from web/src/keating/starter-prompts.ts); then "How should Keating get to know you?" with the two existing track choices relabelled "A few quick choices" ("One screen. Everything on it is optional.") and "Talk it through" (existing description); a "Stored only in this browser" line; primary "Continue". Remove the four explanatory boxes about the composer, side panel, sessions and settings (the interface tour covers them).
3. Stage 2, Model: "How would you like to chat?" / "You can change this later from the header." The three existing access choices as option cards (keep the offline choice desktop-only), with the setup for the SELECTED choice shown inside its card instead of on a separate Setup screen: Keating: "Sign in or create an account" with its existing checking / opening / failed copy and auto-advance once a session exists; own key: "Choose a model and provider"; offline: the existing OfflineTutorSettings panel and "Choose the offline model". Keep the existing "Selecting…" step that selects the hosted default model and its failure copy. NEW: a "Skip sign-in for now" link under the Keating choice that moves on without a session, with the line "Keating asks again when you send your first message." (the app already prompts for access when a hosted model is used without one; verify that path and say what you found). There must always be a way forward from this stage.
4. Stage 3, You (form track): "How should Keating teach you?" / "Preferences, not a test. Keating follows them." One screen, no nested scroll region: "What should Keating call you?"; "Explain things in" (the existing language select); three teaching preferences as kit `Segmented` controls using the existing option values and labels (how much to ask before telling; when you are stuck; tone); "Anything that would make this easier?" as toggle chips for the six existing accessibility switches plus text size (they must apply immediately as they do today); and "Age range" as an optional select with its existing helper text and the existing under-13 note and analytics behaviour (this field is NOT in the mockup; keep it because it changes behaviour). A line "Pronouns, schedule and interests are in Settings → Learning." and a link "Use Anki? Bring your decks" that opens the existing Anki import. Every other field from the old About you / Your learning / How to teach you screens is no longer asked here but must still load, persist and be editable in Settings exactly as before: do not drop stored values.
   Conversation track: on this stage show the existing ProfileIntakeChat (its four prompts, speech input, skip and extraction) with ONE skip control per level (remove the duplicated "Skip this" where the inner "Skip" already exists) and the same label "Fill the form instead" everywhere. Fix the rough edges the inventory lists for it: Ctrl/Cmd+Enter must respect the blank guard; show a visible busy state while extraction runs and catch its failure with a retry; stop the speech recognizer when a question is skipped.
5. Stage 4, Ready: the mascot with "You are set, {name}." (or "You are set." without a name), "Saved on this device. Change any of it in Settings → Learning."; a short summary list of what was chosen (model, language, teaching choices actually set); the proposal review (from the conversation or Anki) inline as dashed cards with Keep / Drop using the existing ProfileProposalReview logic and copy, so "nothing is saved until you say so" stays true (also fix the inventory's noted bug where accepted proposals can be lost if the page reloads before finishing: persist them when applied); the learner's question shown in a read-only composer-like box with "Your question is waiting in the composer"; footer "Show me around first" (only when the tour has not been seen) and primary "Start chatting". Finishing still hands the goal to chat exactly as today.
6. Persistence: keep the localStorage key and the completed/skipped semantics. In-progress records written by the old eight-step flow must resume on the corresponding new stage (map old step ids to the four stages); write new records with the new stage ids. Add tests for the mapping, for skip/finish, for "always a way forward" on the Model stage, and for the profile values that are no longer asked surviving a full run.
7. Tour: keep steps, copy, keys and storage; restyle the card with kit primitives and use `KeatingBot state="pointing-left"` (mirrored with CSS when the target is to his right) on the card.
