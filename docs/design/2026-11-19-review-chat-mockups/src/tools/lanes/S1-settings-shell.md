WHAT TO BUILD
1. Shell (board S1): a named modal dialog (`role="dialog"`, `aria-modal`, labelled by its title; focus moves in when it opens, Tab stays inside, Escape and the close button close it, focus returns to the control that opened it; the page behind is inert and does not scroll). Top bar: "Settings", the "Find a setting" field (`/` focuses it), a quiet "Documentation" link, Close. Left column: the outline (four groups; the open group lists its sections; the current section is marked; a group can carry a short status in words such as "2 unsaved" or "1 needs a key", supplied through the registry). Main column: the current section's rows. Optional right column: an aside a section can supply (a preview, "Right now", "What Keating is told"). Sizes on the kit's scale (see gap-rules "Type roles"): the old 0.75rem to 1rem text and rounded 0.5rem cards go.
2. Groups and sections (map section 7, boards S1 to S3). `groups.tsx` is the single registry: for each group an id, title, glyph, and ordered sections; for each section an id, title, the component to render, optional aside, optional status hook, and the LEGACY ids that must still open it. Initial assignment, mounting the existing components unchanged:
   - Interface: Display and reading; Motion and effects; Chat layout; Companion and sound; Getting around.
   - Learning: Your profile; Teaching (persona, study-plan approval, response comparison); Voice and Live; Recall and predictions.
   - Models and connections: Models for each job; Providers and keys (provider connection, My Models, Custom Providers); Your account (account card, chat sync); Sources and web search; Checking replies (judgement model, Julia, calibration); Offline tutor (when available); Images; How this build is set up (the read-only proxy and renderer notes).
   - Data and support: What leaves this device; Your data; Health; Developer tools.
   Where one existing component currently renders several of these (for example `ProvidersModelsTab.tsx`, `LearningTab.tsx`, `DiagnosticsTab.tsx`), mount it whole under the first matching section and list the other sections as anchors into it for now; say which in your README so the next lanes can split them. Do not edit those files.
