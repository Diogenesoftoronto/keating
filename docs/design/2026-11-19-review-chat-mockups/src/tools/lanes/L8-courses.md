C1 Course library
1. Replace the global Nav + large header with kit `AppBar` (back to chat; title "Courses"; subtitle with the workspace kind: Account / Development / Local workspace; a `SearchField` "Find a course…"; "Assemble manually" as a line button; "Plan with Keating" as the primary). 2. Below it: the mascot (`KeatingBot state="books"`, keeping the existing state changes for requesting/assembling), "What's next to learn?", the existing sentence, and filter chips All / Learning / Teaching with counts (Teaching = you are owner or teacher). Search filters by title and description.
3. Course cards: role chip; "{n} people" (and "{n} here" only if the list data already has presence; never invent it); serif title; description or "A shared course in progress."; a kit `Meter` with "{done} of {total} lessons"; and a last line that says what is next: for learners "Continue" + the next incomplete lesson's number and title (first lesson if none started; "Course complete" if all done), linking straight to that lesson (the workspace route accepts ?lesson=); for owners/teachers with submissions waiting, "Waiting on you" + "{n} submissions to review" linking to the Review tab. 4. A quiet footer row: "Just one paper or topic?" + "Study it at your own pace" (to /learn).
5. Keep the inline assembler and all its states, opening below the header row; keep loading, error and empty states and their copy, with the empty state's two actions shown once each (primary "Plan with Keating", secondary "Or assemble manually").
C2 Course workspace
6. Header: ONE kit `AppBar` row: back to courses; the course title with the existing course switcher on a small disclosure button beside it; the role chip; right side: "Search this course" (opens the existing command palette; show the ⌘K hint), "Add" (the existing add menu), "Keating" (the existing course-scoped chat entry), "Invite" when allowed, and the connection state with "saving…". Then a kit `SubBar` with the Read / Discuss (count) / Review / Build tabs (same visibility rules), and on Read the position "Module {m} · Lesson {i} of {n}" with Previous and Next lesson buttons.
7. Outline (left column at desktop widths; on narrow screens it opens as a kit `Sheet` from a button in the SubBar and the Previous/Next row is the main way to move): module headings; lesson rows with a square that is filled with a check when complete and open when not, the title, the active state, and the unread/comment count; the "Course shelf" as a compact summary at the bottom with the same destinations and permission rules as today. Show "{done}/{total}" in the outline header.
8. Read desk: eyebrow "{module} · {N min | self paced}"; the lesson title in the serif face; summary; "By the end" objectives as chips; the reading in kit `Prose`; then the existing sections in their existing order (private reading fork, lesson sources, artifacts, worked exercise, assignments, course-wide shelves, shared notes), each restyled as kit `Card`s with `Eyebrow` labels and their existing controls and states. The per-lesson "Add document" and "Edit" buttons move into the header "Add" menu and the lesson's overflow (keep them reachable for editors; remove them as loose header buttons). At the end: "Mark complete" / "Lesson complete" (same toggle) and, beside it, a primary button to the next lesson: "Lesson {n} · {title}" (or "Back to the outline" on the last one). Completing does not auto-navigate.
9. Discuss, Review, Build: keep all behaviour and copy; adopt kit `Tabs` for the Build sections and kit buttons, fields, cards and chips for their chrome. Do not restructure CourseBuilder or CourseContentManagers beyond swapping primitives and spacing.
10. Right rail (people): "Here now" with square avatars, names, roles and presence; the progress `Meter` with "{done} of {total}"; "Work with Keating" with the existing presets and "Open the full conversation"; "Study rooms" using the existing `CourseRooms`; "Recent activity". Move the optional "Pear feed" diagnostics out of the rail into a collapsed "Diagnostics" disclosure at its very bottom (only where it renders today).
11. Banners (errors, teacher access request): one at a time in a single slot under the SubBar, most important first, each keeping its actions.
12. Join page: same states and copy; restyle with kit `Card`/`Button`; `KeatingBot state="letter"` on the joining state.
