# Recess review · 20 November 2026

**Fix the answer keys and the ownership of a flight first.** I ran a ready lesson in which the local game awards points for identifying seven as the number that isn’t prime. Separately, a learner can launch while Keating prepares artwork and questions, then lose that flight when the preparation finishes.

The composer strip, three routes out of a thin chat, and reuse of chat typography are worth keeping. Questions, answers and the log already share a Markdown/KaTeX renderer with passive links and images. Second Wind focuses an answer and returns focus to the arena. The session-keyed companion and abort checks are useful foundations. References below are checkout-relative, principally under `web/src/`. “Confirmed” means traced in the working source or reproduced locally. “Suspected” identifies a runtime condition I did not establish.

## A. Ranked findings

1. **High · confirmed by running the builder · A ready chat can teach a false answer.** I gave one tutor turn beginning “The **prime numbers** (two, three, five) each have exactly two positive divisors. The **larger primes** (seven, eleven, thirteen) have the same property. A **divisor** divides a number exactly.” With further sentences about divisibility to clear readiness, the second gate was “Which one isn’t part of **prime numbers**?” with correct-first choices seven, two, three, five. All four are prime. The builder treats absence from a particular list as evidence of nonmembership in its category. Use “Which number was absent from the tutor’s first list?” for a literal list-memory task, or require positive evidence of category exclusion for a concept task. Keep this nested-category fixture in the builder tests. `keating/habits/recess-lesson.ts:1129–1144`, `components/recess/engine/targets.js:93–100`.

2. **High · confirmed by tracing · A late result can restart an active run.** Launch freezes the pack and lesson. The render still requires assets keyed to the *current plan*. Launch a coding chat before readiness finishes, then let Jev downgrade it. The candidate pack becomes null, casting falls back to maths, and the old assets cease to match. React removes the flight, its cleanup can settle spent charge, and loading maths art mounts a fresh engine for the frozen coding pack. A cast-changing enrichment or equipped-kit change can take the same path. Freeze loaded assets, condition, host identity, owner scope and run ID together at launch. A deferred-readiness test should assert one engine start, one final result and at most one settlement. `components/recess/ChatRecess.tsx:95–99,131–133,159–171,194–201,326–330`, `components/recess/RecessFlight.tsx:245–249,268–275`.

3. **High · confirmed by tracing · Starting immediately can initiate model work during action.** Readiness waits for the other-chat scan. Start from a locally ready pack before the scan resolves and its completion starts a Jev operation during flight. A compile started before takeoff can also issue its second transcript-review request after takeoff. Neither effect depends on stage. Preserve immediate launch, cancel pending preparation at launch, and guard each later dispatch with the preparation signal. Restart optional preparation after landing. `components/recess/ChatRecess.tsx:101–129,194–202`, `keating/habits/director.ts:71–80`.

4. **High · confirmed behavior, suspected cross-account impact · Settlement lacks a stable launch owner.** The engine uses launch-time condition, while its end/abandon refs follow the latest parent callbacks. If a scope change leaves the flight mounted, the new callback compares the *new* scope with current scope and can submit the old flight under that identity. The snapshot also remains usable across a scope change until the new read returns. A slow initial read allows launch at the standard 75% charge. Bind the command to scope and ID at launch, wait for a matching snapshot in Care mode, and end the old run explicitly on identity change. Verify with account A flying, then switch to B before landing. Session changes already have a keyed remount. `components/recess/ChatRecess.tsx:135–157,194–205`, `components/recess/RecessFlight.tsx:206–208,240–248`, `components/ChatMascotMenu.tsx:44–47`.

5. **Medium · confirmed · The flight log can promise charge that Care never credits.** Collect a cell, land early with a positive net delta, and the log adds it to starting charge. The UI deliberately skips that dispatch and the reducer likewise caps a quit at zero gain. A rejected write is also swallowed, then “Saving charge…” clears. Render the accepted change from settlement, distinguish an unsaved result, and retry using the same launch ID. Normal completion sets an ended flag before cleanup, so I found no unconditional double debit along that path. `components/recess/ChatRecess.tsx:150–156,269–274`, `components/recess/RecessFlight.tsx:240–243,268–273`, `keating/habits/engine.ts:545–555,582`.

6. **Medium · confirmed · Model enrichment reduces the available forms.** The local builder supports thirteen named kinds and two to four answers. A successful compile replaces the gates and revives with three-answer tuples from six kinds. That removes the local odd-one-out shooting mechanic from an enriched run. Curation, per-kind history and explain-it were separate modules in the snapshot reviewed. Simply calling the recorder on landing would skip the observations because lane, target and revive results omit kind. Merge candidates before choosing, carry item ID and kind through every result, and distinguish an explicit answer from a timeout. `keating/habits/director.ts:11–14,73–84`, `keating/habits/recess-lesson.ts:1396–1397,1456–1463`, `components/recess/engine/core.js:217,235–245`, `components/recess/engine/targets.js:80`, `keating/habits/recess-mastery.ts:38–51`.

A pack can then be labeled Jev-curated. Separately, “Acceleration does not change velocity” contains the vocabulary of “Acceleration changes velocity” and can earn a sound word-overlap grade. ## B. Twelve ideas to try

Sizes are relative engineering estimates. Each entry gives the extra model work per run. The proposed interactions can use the local pack immediately. Any optional compile or assessment finishes before takeoff, while paused, or after landing.

1. **Top 1 · Return to the exact teaching moment (M).** On landing, show “I chose seven” beside “Show me where we covered this.” Carry a session-scoped turn ID and evidence span from `lesson.ts` through `recess-lesson.ts` and the gate result. `ChatRecess.tsx` can land on the real message and offer an editable tutor question about the discrepancy. Code validates the source still exists and handles changed/deleted turns; optional Jev ranks two candidate spans during curation. Zero extra calls on the local path, or one question in the preflight batch. A missed gate now leads somewhere specific.

2. **Top 2 · Change one fact and predict the outcome (M).** Show a worked example from the chat, change one input, then let the player steer to “increases”, “decreases” or “stays the same” before a visual reveal. In `director.ts`, propose a source quote, original case, changed fact, prediction and rationale. Jev checks that the lesson supports a unique prediction. Code checks field lengths, verifies the quote and scores the selected ID. Reuse lane rendering in `RecessFlight.tsx`. One extra item in the existing proposal and preflight judgement batch. If evidence is weak, omit the item. This gives “apply” a different intellectual task from recognizing the tutor’s sentence.

3. **Top 3 · One optional return question next study day (M).** Let the learner bank one concept at landing and see it when they next open that chat. Store a scoped source reference, due learning day and one unused variant alongside practice history. In `ChatRecess.tsx` offer “Try yesterday’s idea” or dismiss. Code owns scheduling, deduplication and the existing rest-day policy. Jev can check the variant’s equivalence during the original compile. No call on return. Track delayed responses as practice observations, with no streak loss or automatic learning receipt.

4. **Rebuild a derivation (M).** Turn three ordered steps from a worked example into collectible fragments. At the quiet inter-wave checkpoint, place them in order using touch, keys or buttons. `recess-lesson.ts` can extract ordered lists and `patterns.js` can schedule the checkpoint. Code validates a permutation and checks the ordering; Jev only judges whether alternative orders are defensible. Zero generation calls for explicit ordered lists and one optional preflight judgement. Skip interchangeable steps.

5. **Match a rule to its example (M).** Present two rule beacons and three concrete examples. The learner docks one example at each matching beacon, with an immediate chance to revise. Add pair IDs and source spans to the pack in `types.ts` and reuse target positions in `targets.js`. A compiler proposes the pairs; Jev checks each match and the competing interpretation. Code owns matching, keyboard equivalents and completion. One small batch before launch, no flight latency.

6. **Find the first wrong step (M).** A boss repeats a worked solution with one changed sign, premise or ordering error. The player tags the first line that breaks, then sees the tutor’s original line. Extend `director.ts` with an original excerpt, proposed mutation and line index. Jev checks whether the preceding steps are valid and the mutation changes meaning. Code aligns the unchanged prefix and renders selectable Markdown rows in `RecessFlight.tsx`. One optional proposal in the compile and two preflight judgements. Unsupported mutations are dropped.

7. **Sort examples with an “insufficient information” destination (M).** Some statements cannot be classified from the chat alone. Let the learner park one in “Need more evidence” and reveal what evidence is missing. Add a three-way relation and source-turn references in `recess-lesson.ts`; Jev assesses support, contradiction or insufficient evidence against the cited excerpt. Code rejects ambiguity, balances the categories and checks the selected bin. One batched preflight Choice per candidate. The source excerpt can be reopened while paused.

8. **Make an appeal part of the game (S).** Add “Two answers fit” to the flight log. Preserve question ID, choices, learner pick and the source excerpt in `recess-review.ts`. On request, Jev judges unique correctness and support after landing; code quarantines disputed items locally pending review, with no penalty to the learner. One optional post-run call, zero wait to return to chat. With judgement off, keep the flag and offer a tutor draft.

9. **Let the learner choose what the next flight covers (S).** Offer “Practise this reply” beside a completed worked example. Pass its stable turn ID through the Recess entry handler and build the pack from that reply plus its immediate question. Code evaluates available gates and offers to widen scope if the selection is too short; Jev may downgrade readiness on the smaller excerpt. Reuse `ChatMascotMenu.tsx`, `lesson.ts` and the existing readiness call. No additional model round trip, often fewer input characters.

10. **Give a thin chat one achievable unlock (S).** A compact plan could say “We have a definition. Let’s work one example.” In `recess-readiness.ts`, ask a closed Choice about the missing ingredient (definition, contrast, worked example or checked application); code maps it to an authored draft and keeps the other-chat and demo actions visible. Re-evaluate on the next completed tutor turn and show the launch button in place. One extra question in the existing readiness request, no generation call.

11. **Offer a quiet flight with the same decisions (M).** When the learner chooses quiet play, Keating flies between encounters automatically, then waits for an answer, with the same art, Markdown and boss reveals. Add an explicit untimed gate phase in `core.js` and a native answer group in `RecessFlight.tsx`. Code owns timing, focus, answer IDs and results. Jev uses exactly the same precompiled pack and makes no extra calls. A learner can switch to this form after a difficult touch or keyboard encounter without losing progress.

12. **Let the learner set the finish line (S).** Offer “One idea” and “Full flight” in the plan. A short run plays one gate and a small boss flourish, then gives a satisfying landing with the option to stop or return to the discussion. `patterns.js` selects a finite script, `ChatRecess.tsx` shows the chosen length, and the habits reducer retains its existing reward limits. Jev may rank the most representative available item preflight; code chooses the script and ending. Zero extra calls. Measure voluntary returns and use of tutor follow-ups alongside replay counts.

## C. What I would simplify

- Keep the single composer entry. Replace the session-storage token, global event and animation-frame polling with one session-bound navigation intent consumed when the destination’s completed lesson is ready. Give a failed switch a visible retry.
- Give preparation, play and settlement distinct owners. One bounded lesson analysis can supply readiness, a local pack and candidate provenance. One immutable run can supply all state needed for teardown, settlement and review. This also makes the “start now” option predictable.
- Preserve the existing local routes and passive Markdown. Drop a rejected candidate instead of padding a pack, and show the worked reference when semantic grading is unavailable. A short valid flight is preferable to a confident wrong answer.
- Before adding more passive effects, prioritize the three experiments above. They can be evaluated by whether a learner can find the original explanation, answer a changed case, and voluntarily return to a concept on a later day. Keep arcade points and observed study behavior separate from claims about learning.
