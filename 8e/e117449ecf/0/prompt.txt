## Safe source-to-shared cutover

There is no safe source cutover today.

`compileOpenUISourceToSharedDocument()` is safe only as a complete-source parser. It loses required semantics:

- A source `Question` can contain a group of questions and emits one aggregate `continue_conversation` action with all `AnsweredQuestion[]`; the bridge emits independent shared questions and the renderer sends per-question actions.
- Source `Quiz` submits a scored aggregate result; shared rendering currently emits individual answer actions.
- Source flashcards complete as a deck-level event; shared rendering emits per-card ratings.
- Fence lifecycle is the only lifecycle used by source persistence. The bridge hard-codes canonical document lifecycle to `"ready"` and drops fence/root/component retention semantics.
- Explicit fence IDs are not message-scoped. `segments.ts` scopes only generated fallback IDs, so repeated explicit IDs collide across messages and legacy localStorage keys.
- `correctMatches` is source-label based, while canonical shared question choices use generated IDs; the compiler does not translate it losslessly.
- Existing source UI state lives in `keating:openui-state:v1:<id>`, which has no lossless migration to receipts.

The earliest safe source cutover is after:

1. contract support for retention separately from lifecycle state;
2. contract support for grouped-question and aggregate quiz/deck completion semantics;
3. scoped identity of `sessionId + messageId + fenceOrdinal + declaredId`;
4. source-state-to-receipt migration;
5. a completed fence has been parsed, compiled, validated, persisted, and only then swapped on a future render—not during streaming or mid-form.

Until then, canonical JSON documents may use the new journal path; browser-source OpenUI must remain on the established source renderer.
