changed this: What changed

Composer ported from web (components/Composer.tsx) — bordered card holding a + actions menu, the input, and a single send-or-stop control that never shows both, with the web's teaching reminder underneath ("keating won't give you the answer — that's the point"). The menu carries Live, Model, and Thinking. The web's right-hand "enter to send" hint is omitted because web hides it on mobile too.

Light mode — theme preference (System/Light/Dark) in a new UiSettingsProvider layered above the theme provider so the stored choice is known before first paint. This surfaced a real bug: the accent green is only contrast-validated as a background, but was used as text colour throughout — 3.04:1 on the light surface. Added a primaryText role (accentText, 4.96:1) and moved every text/icon usage onto it; dark mode is pixel-identical since the two roles coincide there. Splash now has a light default with a dark variant.

Settings — Appearance (theme, font), Chat (interactive cards, raw provider errors, thinking budget), About You. Each is wired to real behaviour rather than stored and ignored:
- Font installs JetBrains Mono + Roboto and flows typography through the theme (theme.type), so the setting restyles the whole app.
- Thinking budget maps per provider (OpenAI reasoning.effort, Anthropic thinking.budget_tokens with max_tokens raised above it and temperature yielded, Gemini thinkingConfig) and is only sent for models the catalog says support it. While adding this I found Gemini's thought parts would have leaked into replies — now filtered in both the streaming and non-streaming parsers.
- Raw errors keeps the provider's text and derives a friendly summary when off, so the toggle works retroactively on an error already on screen.
- About You appends to the system prompt as JSON-fenced background, mirroring the web's framing so it can't override the teaching protocol.

Live — off the tab bar, entered from the composer. Note the Live screen itself is unchanged: it still explains native Live isn't in this build and links to web. I only moved the entry point, as asked.

Courses — native client: /session, list, join-by-code, and course detail with modules, expandable lessons, materials, and members. Teacher access is an explicit opt-in switch on the join sheet, never implied by joining. "Study this with Keating" handch exposed a latent bug wherenewSession() followed by sendMessage() in one tick posted into the previous session; the state ref now        updates synchronously.

Cookie handling uses an explicitjar rather than trusting RN's native persistence; I haven't run it against a live server, so that's the piece I'd verify first on device.
